# خطة إكمال وتسليم منصة كاريير-ميديا البحر الأحمر

**الهدف:** الانتقال من تشغيل إنتاجي قائم إلى تسليم نهائي موثق وآمن وقابل للتشغيل بواسطة فريق العميل.

**مرجع البداية:** حالة 31 يوليو 2026.

**اعتماد العميل:** راجع نائل تادرس حزمة التسليم وخطة الإكمال واعتمدهما بتاريخ 1 أغسطس 2026. لا يعني هذا أن مراحل الإغلاق المستقبلية نُفذت بالفعل.

## معيار الإغلاق النهائي

يُعتبر المشروع جاهزًا للتسليم النهائي عندما تكون النسخة المنشورة مطابقة للمصدر المعتمد، ولا توجد أسرار مكشوفة، وتم حسم الطلبات التجريبية والأدوار، واجتازت الرحلات الحرجة اختبار القبول، وأصبح النشر والنسخ الاحتياطي والاستجابة للحوادث موثقًا ومجربًا.

## المرحلة 0 - تثبيت خط الأساس

**المالك:** المسؤول الفني + Mohamed

**المدة التقديرية:** نصف يوم

1. تسجيل SHA الإنتاج للموقع ولوحة الإدارة.
2. مقارنة `main` مع PR #10 وأي تعديلات محلية غير متتبعة.
3. اختيار مصدر الحقيقة، ثم منع أي نشر من حالة غير مراجعة.
4. تصنيف الملفات المحلية إلى: مصدر، وثائق، مخرجات، مؤقت، أو سر محتمل.

**القبول:** مستودع نظيف معروف المصدر، وقائمة قرارات واضحة لكل اختلاف.

## المرحلة 1 - احتواء الأمان والأسرار

**المالك:** Super Admin + المسؤول الفني

**المدة التقديرية:** نصف إلى يوم

1. فحص الملفات المؤقتة محليًا دون طباعة محتواها في السجلات.
2. إذا ثبت وجود بيانات اتصال صالحة: تدوير كلمة المرور/المفتاح أولًا، ثم حذف الملف وإضافته لقواعد الحماية المناسبة بعد موافقة.
3. تفعيل Leaked Password Protection في Supabase Auth.
4. مراجعة Cloudflare Access: السماح فقط للمستخدمين المعتمدين وحماية رابط الإنتاج.
5. منع توزيع روابط المعاينة غير المحمية.

**القبول:** لا يوجد سر صالح في الملفات أو Git history، وتنجح/تفشل محاولات الوصول حسب القائمة المعتمدة.

## المرحلة 2 - تنظيف واعتماد بيانات الإنتاج

**المالك:** Nael + Accounts + Super Admin

**المدة التقديرية:** يوم عمل

1. مراجعة الطلبات التجريبية في Supabase وPaymob.
2. تحديد Live/Sandbox لكل عملية قبل أي إلغاء أو رد أو تسوية مخزون.
3. اعتماد قائمة الموظفين والأدوار، خاصة دور Adel Mina وحساب Dev TESTER.
4. مراجعة 61 سعرًا والحملة الحالية وتاريخ انتهائها من منظور الأعمال.
5. توثيق أي تعديل في Audit وبمحضر قرار.

**القبول:** لا توجد معاملات اختبار غامضة، وقائمة المستخدمين والأسعار والحملات موقعة من مالك الأعمال.

## المرحلة 3 - صلابة الطلبات والمخزون والدفع

**المالك:** المسؤول الفني

**المدة التقديرية:** 2-3 أيام + مراجعة

1. تصميم rate limit لوظيفة `create_order` بما لا يضر العملاء الحقيقيين.
2. إضافة مدة صلاحية لحجز المخزون غير المدفوع وآلية استرجاع آمنة قابلة للتكرار.
3. منع الازدواج عند إعادة المحاولة، وربط كل تسوية بسبب وسجل تدقيق.
4. اختبار النجاح والفشل وإعادة الاتصال والتزامن في بيئة منفصلة.
5. تطبيق migration بعد عرض SQL والآثار والرجوع والتحقق والحصول على موافقة قاعدة بيانات منفصلة.

**القبول:** لا يمكن استنزاف المخزون بطلبات مجهولة متكررة، والحجز المنتهي يعود مرة واحدة فقط.

## المرحلة 4 - تسوية قاعدة البيانات وسجل migrations

**المالك:** مسؤول Supabase

**المدة التقديرية:** يوم

1. مقارنة `supabase_migrations.schema_migrations` بملفات المستودع.
2. تفسير اختلافات الأسماء والتوقيتات بدل تعديل السجل يدويًا.
3. اختبار إعادة بناء قاعدة محلية جديدة من migrations المعتمدة.
4. تشغيل assertions وSecurity Advisor وPerformance Advisor.
5. توثيق الاستثناءات المقبولة وأسبابها.

**القبول:** يمكن إنشاء بيئة جديدة متسقة، ولا توجد migration محلية غامضة أو تاريخ إنتاج غير مفسر.

## المرحلة 5 - CI/CD والاستضافة والاعتماديات

**المالك:** المسؤول الفني + مالك Cloudflare/GitHub

**المدة التقديرية:** 1-2 يوم

1. مراجعة PR #10 وفصل CI عن النشر إن لزم.
2. إضافة متغيرات GitHub المطلوبة دون كشف القيم.
3. جعل push إلى `main` يبني لوحة الإدارة وينشر إلى مشروع Cloudflare Pages نفسه.
4. حماية previews أو تعطيل توزيعها.
5. معالجة ثغرات npm حسب الأثر، مع إعادة الاختبارات وعدم كسر Next.js/Supabase.
6. توثيق rollback إلى آخر deployment صالح.

**القبول:** build آلي أخضر، نشر يمكن تتبعه إلى commit محدد، وتجربة rollback موثقة.

## المرحلة 6 - اختبار قبول المستخدم UAT

**المالك:** Nael + Mohamed + Accounts + Operations

**المدة التقديرية:** يوم

### الموقع العام

- فتح `/` و`/en` و`/ar` على الهاتف والكمبيوتر.
- ظهور الأسعار والخصم والاتجاه الصحيح دون أخطاء console.
- تجربة الفلاتر وصفحات المنتجات والسلة وواتساب وفيسبوك.
- اختبار طلب خدمة وطلب شراء تجريبي مضبوط دون دفع حقيقي.

### لوحة الإدارة

- تسجيل دخول كل دور واختبار ما يستطيع وما لا يستطيع تنفيذه.
- نشر سعر تجريبي آمن ثم الرجوع عنه في بيئة اختبار.
- تعديل حملة ومسودة موقع، ومراجعة المخزون والطلب وإثبات الدفع والتدقيق.
- دعوة مستخدم، استعادة كلمة المرور، تعطيل مستخدم، ومنع إزالة آخر Super Admin.

**القبول:** جميع السيناريوهات موثقة بنتيجة Pass/Fail، وكل فشل إما مغلق أو مقبول كتابيًا.

## المرحلة 7 - النسخ الاحتياطي والتسليم

**المالك:** Mohamed + Nael + المسؤول الفني

**المدة التقديرية:** نصف يوم

1. توثيق مالكي حسابات GitHub وCloudflare وSupabase وPaymob والبريد، دون وضع كلمات مرور في الوثيقة.
2. اختبار استعادة نسخة احتياطية أو مشروع تجريبي حسب إمكانات الخطة.
3. تسليم الروابط، دليل المستخدم، دليل الطوارئ، قائمة المتغيرات بأسمائها فقط، وسجل الإصدارات.
4. تحديد فترة الضمان، قناة الدعم، أوقات الاستجابة، وما يعد طلب تطوير جديدًا.
5. توقيع محضر الاستلام النهائي.

**القبول:** يستطيع فريق العميل تشغيل المنصة وإضافة مستخدم ومعالجة طلب وتنفيذ rollback دون اعتماد كامل على المطور الأصلي.

- كل تغيير إنتاجي له موافقة مستقلة، وخطة رجوع، ونتيجة تحقق.
- لا تُستخدم هذه الخطة كتصريح تلقائي لتعديل قاعدة البيانات أو الاستضافة أو دمج أي PR.
